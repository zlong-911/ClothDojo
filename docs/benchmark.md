# ClothDojo 实验规划

本文只记录已经讨论清楚的方向。ClothDojo 的主要贡献是严重褶皱服装展平 benchmark 和配套数据，不以提出新模型为目标。

## 为什么选择这个任务

布料状态高维，而且褶皱会造成严重自遮挡。模型往往不能从一帧图像确定衣服的结构、正反面和层叠关系，只能在操作过程中继续观察和修正。

不同服装还具有不同的袖长、开口、分支、尺寸和纹理。甩动需要动态控制，后续拉伸、翻面和局部调整又要求细粒度闭环控制。因此，这个任务可以同时检验模型的状态理解、连续控制、错误恢复和跨资产泛化。

这里主要研究 garment structure 或 morphology。顶点数受 mesh 分辨率影响，只作为资产记录，不直接代表任务难度。

## 开源环境贡献

ClothDojo 将公开基于 Style3D 的动态布料交互环境。它在单张 RTX 5090D 上可以保持约 20 Hz 的端到端遥操交互，支持甩动等动态双臂操作，并统一服装资产接入、遥操采集、轨迹记录、SFT、rollout、HIL 和重渲染入口。

旧项目还实现了跨机器人轨迹 retargeting，已覆盖 Piper、ARX X5、ALOHA、Franka Panda 和 UR5e + 2F-85。它通过统一抓取坐标、IK、关节与碰撞约束、夹爪语义和自由运动重定时迁移轨迹，再用完整动力学 rollout 验证目标机器人动作。几何 retarget 阶段复制布料状态，本身不能证明轨迹在目标本体上可执行。

这部分迁移到 ClothDojo 后，作为环境能力和多机器人结果展示；第一阶段不扩展为完整的跨本体模型 benchmark。环境代码、机器人与服装资产、生成数据及必要的来源和许可记录均计划公开。

## 任务怎么评测

- 正式面板固定为 `balanced200_20260901`：200件衣服，100件seen与100件unseen；
  每件4个冻结初态，共800个固定case，推理重复另计。`benchmark run`、`score` 和
  `summarize` 均校验同一面板、初态、模板、协议与划分身份。现有24资产、每资产
  4初态的96-case面板只用于快速开发、诊断和历史比较，不再形成正式评测结论。
  不同模型使用同一批配对初态与预定policy seeds；不能以反复运行旧面板代替资产扩充。
- 正式执行只有 `benchmark run --config <run.yaml>` 一个入口。run config 绑定模型、
  执行方式和 deployment；Coordinator 统一启动独占策略服务、分配互斥多机 trajectory
  shard、补齐缺失case、离线评分和清理进程。节点Worker不写condition元数据，部署变化
  不改变冻结case、policy seed或评分身份。
- seen/unseen 按各checkpoint的实际训练数据溯源，不沿用历史面板的12/12标签；
  当前1838 episode模型在旧面板实际覆盖13个资产，另11个未见。比较泛化时使用
  对待比较模型均未见且未用于调参的确认集合，镜像或其他派生副本不算独立新衣服。
  seen组也使用未参与训练的全新初态；两组各100件的分组依据随面板冻结，不按模型
  重新抽衣服。训练覆盖不同的模型另外报告实际覆盖，不能将已训练资产仍解释为未见。
  unseen资产及其派生轨迹不得进入被报告为未见的模型的SFT、CFG或其他训练阶段。
- 推理文本按模型的实际训练文本对齐：优先看 launch manifest 的 `training_prompt`，
  历史模型参考 `tasks.jsonl`。当前面板接受 `flatten the shirt`
  和 `Flatten the shirt.` 两种已使用的文本，原样记录各自 scenario fingerprint。
  文本不同的结果不能冒充严格同 scenario 的单变量对照。
- 每次正式比较在运行前冻结面板与样本量，按预定预算完成；缺少case、事后改变
  资产组成或仅运行smoke时，不冒充完整面板结论。新旧面板的分数不直接作严格配对比较。
- 初态由衣服随机 `SO(3)` 旋转、随机固定一点、自然垂落和释放产生。
- 只剔除未落桌、未稳定或异常接触等无效状态，不筛背面朝上、局部翻面和严重自遮挡。
- canonical target 使用默认自由沉降状态；rigid 取绕工作台 z 轴
  `0°/90°/180°/270°` 四种朝向中的最小误差，`45°` 不算等价朝向。
  只保存一个模板，评分时处理旋转；XY 平移不惩罚，NOCS 顶点对应和高度误差保留，
  deformable 定义不变，翻面不因此成为等价状态。
- 成功继续使用项目已有的 deformable 和 rigid distance 阈值，不增加 workspace 或 coverage 判据。
- 初态难度由 initial deformable、rigid 和 combined distance 表示。
- 资产难度由人工按结构、实际尺寸和易翻面程度分组；这些标签用于后续分层与划分，不影响当前数据生成。

## 数据怎么产生

纯色布料缺少稳定的视觉参照，人和模型都不容易辨认衣服局部及正反面。NOCS 将 canonical rest mesh 的归一化坐标编码成 RGB，在不改变 VLA 输入形式的前提下提供更清楚的几何线索。

数据路径是：

```text
NOCS 人类示范
  → SFT 训练 NOCS 数据代理
  → rollout 和 HIL 改进数据代理
  → 数据代理从全新随机初态生成成功轨迹
  → 回放同一物理轨迹，生成随机化、高保真 RGB 数据
  → 训练普通 RGB VLA/WAM
```

NOCS 只服务于数据代理。下游模型和正式部署不需要 NOCS，也不访问粒子状态。

当前 NOCS 提供的是归一化空间位置，不是袖子、领口等人工语义标签。它能否形成有效的跨资产对应，需要通过 seen/unseen asset 实验验证。“NOCS 让人工采集更容易”只作为设计动机，不作为论文的量化结论。

数据代理训练期间产生的失败和 HIL 轨迹用于继续改进代理。对下游发布的主体是代理自主产生的成功轨迹。下游模型若需要失败数据或 HIL，应从自己的 rollout 中产生。

成功轨迹可以包含中途失败和恢复。发布前计划在所有成功时刻中找到 combined distance 最低点，并裁掉后续动作，使轨迹终止在有效的最佳状态。项目已有成功阈值、`confirmed_step` 和 `best_observed_step`，裁剪逻辑尚待实现。

当前先构建一个不区分 seen/unseen 的候选轨迹池。约 607 个已接受资产各生成 5 条成功轨迹，确认代理成功率和成本后扩展到每资产 20 条，预计约 1.2 万条；再选 50 个代表性资产补到每资产 50 条，用于区分资产广度与单资产数据密度的作用。

每个生成目标由 `asset_id + initial-state seed/state` 唯一确定，必须来自全新随机初态。第一阶段每资产 5 个成功目标最多尝试 20 次；失败目标进入数据代理的 HIL，不允许通过重新抽取更容易的初态替换。每次尝试均记录初始 distance、结果和 HIL 历史，最终按初始 distance 分析难度，不在生成前筛除困难状态。

## 实验要回答什么

| 问题 | 主要对照 | 结论依据 |
| --- | --- | --- |
| NOCS 是否让数据代理更容易学习？ | 相同物理轨迹分别渲染为 NOCS 和纯色，使用相同模型与训练预算 | seen/unseen asset 上的成功率和 distance；同时比较多档数据量 |
| 代理是否真的扩展了数据分布？ | 原专家数据、重复原数据、重渲染原轨迹、加入代理新轨迹、加入代理新轨迹并重渲染 | 固定训练帧数或步数，比较下游 RGB 模型表现 |
| 模型能否适应视觉变化？ | ID、未见纹理、未见背景、未见光照及组合变化 | 在相同资产和初态上做闭环 rollout |
| 模型能否适应新服装？ | 训练资产、同类未见实例、未见结构组合 | 按人工资产难度和初始 distance 分层报告 |
| 当前热门机制是否有用？ | observation/action history、memory、WAM、action chunk、RTC | 看收益是否集中在高难初态和 OOD 条件，而不只看平均值 |
| 模拟数据能否补充真机数据？ | 固定真机数据量，比较 real-only 与 real + rendered trajectories | 真机成功率和 distance |

NOCS 数据量实验用于区分样本效率和最终能力。比较 NOCS 与纯色时，物理轨迹、动作、模型和训练计算都必须相同；若加入 HIL，还要控制相同的介入预算。

数据扩充实验需要区分两件事：新物理轨迹扩展状态—动作分布，同一轨迹的多次渲染只扩展视觉分布。两者不能混成一个“数据量”。

纹理通过简单语义标签分配到合理的服装类型。默认测试使用语义合理但未见的纹理；额外交换服装结构与纹理，可以检查模型是否依赖错误的 texture shortcut。

离线重渲染可以生成训练数据和配对视觉诊断，但不能代替闭环评测。正式成功率必须来自模型实际看到相应视觉条件后的 rollout。

## 数据与测试隔离

- 当前数据代理生成阶段不预先冻结 seen/unseen asset；所有轨迹保留资产、固定初态和生成过程的完整身份。
- 候选轨迹池完成后，再为下游模型分配 train、seen 和 unseen assets；属于 unseen assets 的生成轨迹不得进入该模型的训练集。
- 正式评测使用另外生成并冻结的全新 initial-state seeds 和状态池，不复用候选轨迹的初态。
- 不同模型使用相同的 test case manifests、policy seeds 和评测时长。
- 同一资产的不同视觉条件使用相同初态，以隔离纹理、背景和光照影响。
- 数据规模分别报告唯一物理轨迹数和渲染副本数。

资产测试分为：训练资产上的新初态、同类未见实例、未见结构组合。裤子资产目前不足，不为了类别完整而加入；长袖、连衣裙等大尺寸或易翻面的资产可以作为较难分组。

## 结果怎么报告

主指标使用 **90 秒结束时的成功率**（`success_at_end`），按现有 deformable 和 rigid
双阈值判断，不要求每一步模拟逐位一致。AUC、最佳状态、终态距离和曾成功率用于辅助诊断，
不以 AUC 作为主要模型选择依据。初始 distance 用于画难度曲线。

新200衣服面板分别报告seen和unseen的资产等权终态成功率及区间；综合成功率为
`0.5 × seen成功率 + 0.5 × unseen成功率`，代表预定的均衡测试分布，
不以重复次数或训练数据中的衣服频率改变两组权重。组内区间与综合区间分别计算，
不能将综合分的精度视为每个100衣服分组的精度。

`benchmark summarize` 的 `success_at_end_count`、`success_at_end_rate_micro` 和
`success_at_end_rate_asset_macro` 分别表示终态成功数、逐 case 成功率和资产等权成功率；
当前每件衣服均有4个初态，后两者相同。配对字段 `paired_success_at_end_rate_delta`
及 `success_at_end_wins/losses/ties` 使用终态判定。旧 `success_*` 字段继续表示过程中曾成功，
含义不变，不能与终态成功混用。

最优状态和90秒终态均报告 deformable、rigid、combined distance；当前
`combined = 0.65 × deformable + 0.35 × rigid`，按模板尺度归一化，越低越好，
不是百分制得分。`best_observed_*_distance_mean` 先对每条轨迹取评分采样点中
combined 最小的同一个时刻（包含初态，不限定成功帧），再对所有 case 求均值；不把 deformable 与 rigid
各自的独立最小值拼成同一状态，也不在重复轮次中挑最好一轮。
`terminal_*_distance_mean` 为90秒末帧的对应均值。连续距离补充成功率的诊断信息，
不意味着其跨轮波动天然更小。

检查分数可靠性时，固定模型、初态、policy seed、批次与部署，重复完整面板并保留全部轮次，
报告平均分和实际轮次波动，不择优挑选单轮。重复运行误差与资产抽样不确定性分别报告；
同一衣服的多个初态和重复运行不能当作同等数量的独立衣服。重复次数与可区分的分数差距
需要由实测波动决定，不能预设96 case足以稳定区分小幅提升。

默认评测结果表和对用户的实验汇报包含最优与终态的 deformable、rigid、combined
六项距离，并保留 AUC combined distance、曾成功率、终态成功率及抬起时间（秒）。
抬起时间不是可省略的附加列；
复用旧冻结运行时或历史评分时，也要从完整轨迹离线补算后一起报告。
确实缺少可用轨迹时应明确标为未计算，不省略该列、不把缺失当作0。

离线评分默认计算 `airborne_seconds`（抬起时间）：至少50%的布料顶点高于该资产自然平铺模板的中位高度5 cm，按评分采样频率对浮点指示值做梯形积分。表格报告每条轨迹的平均累计秒数，标准汇总字段为 `airborne_seconds_mean`；这不是整件衣服完全离桌的时间，也不参与 reward 或成功判据，没有越短越好的预设。

成功的两个阈值分别从完整、非镜像的人工轨迹终态估计。每个资产总权重相等，
资产内每条轨迹权重为 `1 / 该资产轨迹数`；对 deformable 和 rigid 各取
`加权中位数 + 3 × 1.4826 × 加权 MAD` 作为上侧异常值分界。两项独立计算，
不迭代剔除、不先按另一项筛选，也不删除被判为异常的原始训练轨迹。
具体阈值以 `configs/evaluation/shirt_flatten.yaml` 为准。

指标或阈值更新后，使用 `benchmark score --rescore-from <原采集协议.yaml>`
从完整轨迹重算；保留原采集协议，新结果绑定当前评分协议。任务、时长和模板
生成条件必须保持一致，不能把重评分当作新 rollout。不同评分口径的表格不可混用。

评分前会核对每条轨迹与采集条件的模型、执行配置、视觉与观测配置，以及初态池和
随机种子。来源不一致或缺失时拒绝评分，并保留已有结果，不能混入其他运行的轨迹。

暂不人工划分 fling、拉伸、翻面和 pick-place。动作本身连续且经常穿插，强行分类会引入主观规则。需要解释行为时，使用 distance 曲线、最佳状态到终态的退化、成功时间和动作量。

## 后续方向

布料质量、刚度、阻尼和摩擦会影响甩动；机器人跟踪带宽、速度/力矩限制、延迟和抓持稳定性也会影响结果。这些参数先确定可信范围，再作为独立 dynamics robustness 实验，不混入第一轮视觉 OOD 对照。

更进一步可以让外观与动力学在训练中相关、测试时交换，用来检验模型是否依赖材质外观猜测动力学，以及 memory/WAM 能否根据动作结果进行修正。这个实验解释力强，但实现成本较高，暂不作为第一阶段要求。

## 近期需要补齐

1. 实现成功轨迹的最佳有效状态裁剪与发布。
2. 补齐资产语义与难度标签；候选轨迹池完成后再生成 seen/unseen manifests 和独立 test state pools。
3. 建立纹理语义标签及 train/test material split。
4. 接通高保真随机视觉条件下的闭环评测。
5. 从旧项目迁移跨机器人 retargeting，并保留几何转换、动力学 rollout 和成功复验的边界。
